## 詰まったポイント
## 1. uv と VPN 問題

### エラー内容

```bash
~/Project$ uv sync
Using CPython 3.13.4
Creating virtual environment at: .venv
⠧ perplexity-poc==0.1.0error: Failed to fetch: `https://pypi.org/simple/python-dotenv/`
  Caused by: Request failed after 3 retries
  Caused by: error sending request for url (https://pypi.org/simple/python-dotenv/)
  Caused by: client error (Connect)
  Caused by: Connection reset by peer (os error 104)
```

どうやら、ネットワーク問題によりPyPIへの通信が遮断・不安定（？）になっていて、python-dotenv を取得できていない。。。

### 結論
 `uv sync` が失敗するのは**企業VPNの接続が切れていたのが原因**で、依存ライブラリをインターネットから取得できない状態だったようです。

---

### uv sync がやっていること

```text
1. pyproject.toml を読む
2. 必要なライブラリ一覧を決定
3. PyPI（外部）にアクセス
4. ライブラリをダウンロード
5. .venv に配置
```
→③の**PyPIへのアクセス** が通らないと失敗するようです。

自分の場合、業務中にVPN接続を義務付けられていることが大前提なので、このエラーは必然でした。


## uvについて簡単に
経験ある方なら一度は見たことあるはずですが、Pythonプロジェクトの依存関係を管理できるモダンなツールです。個人開発でもチーム開発でもuvで管理しておけば問題ないかと思います。

### 「Python パッケージ」として認識させる
基本的にはpyproject.toml を読んで、Pythonプロジェクトを判別します。
しかし次の構成だとパッケージとして認識されません。

```
Project/
├ app.py
└ pyproject.toml
```

### __init__.pyを配置しましょう
Python特有なのですが、__init__.pyは、ディレクトリをパッケージとして扱うためのファイルです。これがないと、そのフォルダはただの「スクリプト置き場」扱いになります。

```
xxx/
└ __init__.py
```


uv run に対応する最小構成例
```
Project/
├ pyproject.toml
├ uv.lock
├ src/
│  ├ __init__.py
│  └ app.py
└ README.md
```
