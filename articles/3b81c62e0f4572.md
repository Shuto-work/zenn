## はじめに
RAG（Retrieval Augmented Generation）システムの開発において、避けて通れないのが **LLMの精度の評価** です。特にセールスナレッジのように、正解が一つではないドメインでは、人手による評価コストが膨大になりがちです。

**「これこそAIで効率化できるのではないか？」** 
そんな疑問が生まれるのも自然でしょう。

今回、人手評価の代替を目指して、RAG評価の標準的フレームワークである **RAGAS** を導入・検証しました。その結果見えてきた、活用できるパターンと活用の限界について共有します。

![RAGアーキテクチャ全体像](../images/RAGAS%20System2.jpg)

## 検証の背景と目的
セールス担当による人手評価のコスト・時間が課題でした。本検証では、過去10年のセールスナレッジを検索・回答するRAGシステムを対象に、RAGASが人間評価の代替になり得るかを検証しました。

* **評価対象**: ユーザー（セールスマン）の質問に基づいたLLMの回答と関連事例。
* **従来の人手評価**: よくある質問を30個用意し、セールス担当者がLLMの回答に対して「関連性」と「正確性」の観点から 0, 0.5, 1.0 の3段階でスコアリング。

## 検証結果：人手評価との大きな乖離

結論から言うと、
正解回答のないRAGでは、**RAGASによる人手評価の完全代替は困難**という判断に至りました。

### 1. 相関関係が見られない
RAGASのスコア（0.0〜1.0の連続値）を人手の3段階評価にグルーピングして比較しても、明確な相関は見られませんでした。

### 2. 乖離の要因：文脈理解と評価基準のズレ
なぜAIと人間で評価がズレるのか、その要因は「構造的な違い」にあります。

| 評価者 | 視点・特徴 |
| :--- | :--- |
| **人手（セールスマン）** | RAGASと似たような関連性・正確性の観点で評価。ただし、経験に基づく**暗黙知**、業態・商流の理解、「実務で使えるか」という視点が含まれている。 |
| **RAGAS** | あらかじめ定義されたロジックに基づく評価。ドメイン知識やセールス文脈を持たない |

RAGASは主に単純な意味的類似性でスコアリングしますが、セールス現場では **「1年前の成功事例は、今の特定の顧客提案に有効か」** といったコンテキストによる判断が求められるため、ギャップが生じました。

![評価のズレ](../images/RAGAS%20Human%20Score%20Diff.jpg)


### 3. コンテキストを整えるために
上記のギャップを埋めるには、RAGASのようなフレームワークを利用せず、独自のLLM as a Judgeとしてフルスクラッチで設計する必要がありました。


例えるなら、LLMを新人セールスマンとして見立てて、業界用語やベテランの知見を教えていくようなものです。

専門用語や「この成功事例は使える・使えない」などの経験則に基づく暗黙知や判断軸を言語化してLLMに渡す必要があります。

## プロンプトエンジニアリング例
### 専門用語辞書
簡単な例です。

```
あなたは「お弁当・中食（なかしょく）業界」の業務に精通したアシスタントです。
以下の【専門用語辞書】を必ず参照し、ユーザーの質問文および回答生成時に
用語の意味を補完・置換しながら理解してください。

【専門用語辞書】
- 配荷：店舗・チェーンへの弁当導入および継続的な販売展開。単発納品ではなく、定番化を含む概念
- 定番採用：期間限定ではなく、通常売場で継続的に販売される状態
- 売場面積：弁当が陳列されるスペース。フェイス数・平台・温冷ケースを含む
- SKU：取り扱い品目数。弁当の種類数を指す
- 廃棄ロス：売れ残りによる廃棄。バイヤー判断で最も重視される指標の一つ
- 本部商談：個店判断ではなく、本部・責任者レイヤーでの導入可否判断の商談

【指示】
- ユーザー入力に専門用語が含まれる場合、現場実務の暗黙知を補って解釈すること
- 回答では、業界未経験者にも理解できるよう背景を補足して説明すること
- 辞書にない用語でも、文脈上お弁当業界特有と判断できる場合は同様に扱うこと

```


### 判断基準の言語化

```
あなたは「お弁当営業を指導・評価するベテラン営業マネージャー」です。
これから提示される【新人営業の回答】を読み、
実務的に「合格かどうか」を判断してください。

あなたの役割は「良い文章か」ではなく、
**実際の営業現場で通用する思考・判断になっているか**を評価することです。

────────────────
【評価観点（必ず全て確認）】
1. 判断レイヤーの特定
   - 店舗判断か、本部判断かが明確に区別されているか

2. リスク理解
   - 廃棄ロス、売場制約、オペレーション負荷など
     相手が嫌がるポイントを正しく捉えているか

3. 因果関係の説明
   - 「なぜ売れるのか」「なぜ廃棄が減るのか」が
     感覚ではなく理由として説明されているか

4. 継続性の視点
   - 単発企画ではなく、定番化・継続配荷につながる視点があるか

5. 再現性
   - 他店舗・他チェーンでも横展開できる内容か

────────────────
【評価ルール】
- 以下の3段階で評価してください
  - 合格：現場に出しても問題ない
  - 要改善：方向性は良いが、判断が浅い
  - 不合格：営業として危険、または思考がズレている

────────────────
【出力形式（厳守）】
1. 総合評価：〈合格 / 要改善 / 不合格〉
2. 評価理由（最大3点まで、箇条書き）
3. 改善アドバイス（新人営業に向けて1〜2文）

※ 感情的な表現や精神論は禁止  
※ 「売れると思う」「頑張る」などの曖昧表現はマイナス評価

```

## 今後の展望：LLM-as-a-Judgeとの向き合い方

検証を通じて、今後のRAG評価における現実的な方向性が見えてきました。

### 1. 補助的な活用に留める
LLMによる評価は、人間を完全に置き換えるものではなく、あくまで「補助」として位置づけるのが現実的です。
* システム内部（モデルやプロンプト）を変更した際の品質モニタリング
* 改善点の発見や、相対比較・傾向分析（Before / After）への活用

### 2. 人手評価に近づけるためのアプローチ
もし代替を目指すのであれば、汎用フレームワークを超えた、フルスクラッチの設計が必要になります。
* **専門用語辞書の付与**: 業界特有の用語をLLMが理解できるよう置換・補足する
* **判断基準の言語化**: セールスマンの判断基準をプロンプトとして明示的に組み込み、「新人セールスマン」を教育するように設計する

ちなみに、国立情報学研究所でも同じような見解が出ていました。

## まとめ
RAGASは、セールスナレッジのような **「正解が多種多様で、文脈依存度が高いドメイン」**では、そのままでは機能しにくいのが現状です。「AIがAIを評価する（LLM-as-a-Judge）」分野は日進月歩ですが、現在はまだ人間との「イタチごっこ」の状態にあります。

一方で、
正解データが明確なシステム（事実確認ベースなど）や、モデル変更（Gpt-4o → GPT-5への切り替え等）に伴うモニタリング指標としては非常に有効です。
